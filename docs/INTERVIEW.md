## 1. STAR 三档话术

### 1.1 · 30 秒版（自我介绍带项目）

> 我在 2025 年自主开发了一个 IM 股指期货的 T+0 量化交易机器人——QuantAI。
> 系统对接天勤、东财、金十、日韩指数 **4 个数据源**，用 LLM 做决策。核心是 **4 级信心评分算法**
> 和 **基于 ATR 的波动率自适应止损框架**，单笔风险硬约束在 2% 以内。
> 从最初 770 行单文件重构到 **14 个 SOLID 模块**，关键路径有单测覆盖。

### 1.2 · 1 分钟版（项目概览）

> QuantAI 起因是想验证 LLM 在金融时序决策上的可行性，IM 期货是 T+0 适合日内高频验证。
>
> 系统分四层：
> - **数据层**：天勤 TqSdk 拿期货实时行情、东财 efinance 拿指数 K 线、金十快讯 + 日韩指数辅助
> - **决策层**：把 6 个周期（5min/15min/30min/60min/日线/周线）的技术指标 + 基差 + 新闻摘要打包成 Prompt 给 LLM，
>   要求严格 JSON 输出包含 action、SL、TP、confidence 四个核心字段
> - **风控层**：算 5min/15min/60min ATR，定义 Stress Level = 5minATR / 60minATR，
>   应激时暂停开仓、收紧止损
> - **执行层**：分即时单和条件单，所有订单有超时撤单和失败重试
>
> 最有意思的设计是 **4 级信心评分**：信心 0.55-0.65 试错、0.65-0.75 轻仓、0.75-0.85 中仓、0.85+ 重仓，
> 最大手数随信心动态调整，避免情绪化满仓。
>
> 后来从 770 行单文件重构到 14 个模块，引入云端-本地持仓一致性校验、JSONL 决策日志、钉钉告警，**可观测性大幅提升**。

### 1.3 · 2 分钟版（深度技术细节）

在 1 分钟基础上扩展：

> **Prompt 工程**：迭代了 V1→V2→V3 三个版本。
> V1 输出自然语言解析失败率高，改成强制 JSON；
> V2 把信心分硬编码到 Prompt 让 LLM 自由发挥，加了评分规则约束；
> V3 加了波动率环境说明让 LLM 动态调整止损倍数。
>
> **遇到的最大的坑**是天勤账户本地和云端持仓不一致导致重复开仓。
> 加了 `PositionManager.reconcile_with_broker()` 启动校验，
> 用券商 API 真值覆盖本地状态后彻底解决。
>
> **核心风控创新**：
> 1. **止损 ratchet**：止损只允许"朝保护利润方向"移动；放宽止损需要 confidence ≥ 0.75
> 2. **加仓 4 重门槛**：信心 ≥ 0.85 + 已持 < 3 手 + 价差 ≥ 1×ATR + 浮亏 > -1.5%
> 3. **止损后 15min 冷却**：同向禁开，避免"复仇式"开仓
> 4. **emergency_mode 自动复位**：空仓 30min 后自动解除应急模式
>
> 现在规划升级成 **LangGraph Multi-Agent**，把信号、风控、执行拆成三个独立 Agent，
> 用 StateGraph 协调，Send 并行触发多周期信号分析。

## 2. 高频追问 Q&A

### Q1 · ATR 怎么算？为什么用 14 周期？

> **算法**：14 周期 TR 的滚动平均：
> ```
> TR = max(high-low, |high-prev_close|, |low-prev_close|)
> ATR = TR.rolling(14).mean()
> ```
> **选 14**：是 Wilder 1978 年提出的经典值，约对应 3 个交易日，既能过滤噪声又能反映短期波动。
> IM 期货日内有 4 个小时交易，14 个 5min K 线约 70 分钟，是日内中期波动的合理基准。

### Q2 · 为什么选 5min / 60min 做 Stress Level？

> **5min**：日内最短周期，捕捉行情突变
> **60min**：机构常用基准周期，代表"中期常态"
>
> 比值 = 短期 / 长期，反映短期波动率对长期基准的偏离。
> 灵感来自医学**应激指标**——人体应激时心率/血压会突然偏离静息基准。
>
> 设阈值 2.0：经回测，2.0 倍以上意味着短期波动是中期的 2 倍以上，
> 大概率是事件驱动行情，不适合趋势交易。

### Q3 · LLM 误判怎么办？三层兜底机制具体是？

> **第 1 层 · Prompt 约束**：要求严格 JSON + 信心评分量化 + 最小信心 0.55 阈值，
> < 0.55 直接返回 WAIT
>
> **第 2 层 · 风控硬约束**：
> - 止损 ratchet：LLM 不能在低信心时放宽止损
> - 单笔风险硬约束：自动削减手数到 ≤ 2% 账户权益
> - 最小止损距离：< 0.8×5minATR 自动放宽
>
> **第 3 层 · 应急平仓**：`check_stop_profit` 每个 tick 监控价格触及 SL/TP，
> 平仓失败进入 `emergency_close` 持续重试直到成功

### Q4 · 为什么 Prompt 输出 JSON？

> **可解析**：Python `json.loads` 一行搞定，正则只需提取 `\{.*\}`
> **可量化**：confidence 字段允许程序化分级决策
> **可程序化执行**：action / volume / SL / TP 直接对接订单 API
>
> 早期试过自然语言输出，**解析失败率超过 15%**，且 LLM 会写"建议谨慎做多"这种模糊措辞，
> 无法量化触发交易。

### Q5 · 云端-本地持仓不一致是怎么发现的？怎么解决？

> 一次手动平仓后重启程序，发现本地状态显示 `LONG 2 手`，但实际券商已空仓。
> 系统按本地状态继续做多决策，差点重复开仓。
>
> **解决**：`PositionManager.reconcile_with_broker()` 启动时调 `api.get_position()`，
> 若云端方向/手数与本地不一致，**用云端真值覆盖本地**并发钉钉告警。
> 这是最后一道防线，比 LLM 决策更可信。

### Q6 · 14 模块怎么分的？分层依据是什么？

> 按 SRP（单一职责）+ 依赖方向单向：
>
> **基础层（无依赖）**：config / models / logger / notifier
> **数据层**：market_data（合约+ATR+基差）/ news_manager / jp_indices / performance
> **业务层**：risk_manager / position_manager / ai_decision / order_executor / conditional_orders / rollover_manager
> **编排层**：system.py + execution_pipeline.py
>
> 编排层是唯一允许"知道所有模块"的位置，其它模块只能向下依赖。
> 这样改风控参数不用翻整个项目，加新数据源也只动数据层。

### Q7 · 为什么不直接用 backtrader 这类回测框架？

> backtrader 是为传统因子策略设计，事件驱动模型重，**改 Prompt 一次要重启整个 backtest**。
> 我的核心是**验证 LLM 决策 + Prompt 迭代**的可行性，需要：
> - 每条决策可单独回看（→ JSONL 日志）
> - Prompt 改完立即看效果（→ 实盘小仓位 + 模拟盘）
> - 风控和策略解耦（→ SOLID 分层）
>
> 所以自建轻量回测 `backtest_core.py`，本质是把历史 K 线"重放"给 LLM，
> 快速验证不同 Prompt 版本的胜率差异。

### Q8 · LLM 调用成本？日均花费？

> GPT-4o-mini 单次决策成本约 **$0.001**（约 0.007 元人民币）：
> - 输入：约 4500 tokens（系统 prompt 2000 + 技术数据 1500 + 新闻 1000）
> - 输出：约 200 tokens
>
> 5 分钟一次决策 + 行情触发，1 天约 **1-2 美元**。
> 用 DeepSeek 或火山方舟可以降到 1/3，长期跑实盘 LLM 成本完全可控。

### Q9 · 实盘收益如何？

> （⚠️ **不报具体数字** ）"风控优先，迭代了 3 版 Prompt 才敢小仓位实盘验证。
> 系统持续运行了 X 个月，**零重大故障**，所有交易都在 2% 单笔风险约束内。
> 目前还在调参阶段，重点是优化信心分阈值和短/波段切换逻辑。"

### Q10 · 为什么不用 RL 或传统量化？

> 三个考量：
>
> **1. RL 需要大量样本训练**，IM 期货日内一年约 250 个交易日 × 4 小时 = 1000 小时，
> 数据规模不够支撑稳健的 RL 训练。LLM 是 zero-shot/few-shot，迭代成本低。
>
> **2. 可解释性**：传统量化因子（动量、反转、波动率）的组合权重黑盒，
> LLM 给出的 reason 字段可读，方便调试 Prompt 和发现失败模式。
>
> **3. 业务对齐**：LLM 天然能处理新闻摘要、政策信号这类非结构化输入，
> 这是传统量化的盲区。
